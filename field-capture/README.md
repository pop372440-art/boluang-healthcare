# แอปเก็บข้อมูลภาคสนาม • Supabase Auth

ชุดนี้เป็น **ซอร์สแอปภาคสนามแยก** ไม่ใช่หน้าเว็บ Health Care และไม่ใช่ Sheets bridge `google_apps_script.gs` ที่อ่านทะเบียนอย่างเดียว ยังไม่ได้ deploy ไปยัง Apps Script จริง เพราะเครื่องมือที่เชื่อมอยู่ไม่พบซอร์สโปรเจ็กต์เดิมและไม่มีความสามารถจัดการ Apps Script deployment

## สิทธิ์บัญชี

ใช้ Supabase Auth โปรเจ็กต์เดิมได้ แต่แยกสิทธิ์จาก `healthcare_role` และ `healthcare_villages` ผู้ดูแลต้องตรวจรายชื่อเจ้าหน้าที่จริงก่อนกำหนด **app_metadata** (ไม่ใช่ user_metadata):

```json
{"field_collector": true, "field_villages": [1, 2]}
```

ให้ผสานเฉพาะสองค่านี้กับ metadata เดิม ไม่ทับค่าอื่น ไม่ให้ผู้สมัครใหม่กำหนดสิทธิ์เอง บัญชีต้องยืนยันอีเมลแล้ว มี field_collector เป็น boolean true และมีหมู่บ้านที่รับผิดชอบ 1–13 อย่างน้อยหนึ่งหมู่ แม้เป็น Admin Health Care ก็ไม่ได้รับสิทธิ์ภาคสนามอัตโนมัติ ชุดโค้ดนี้ไม่ได้สร้างบัญชี ส่งอีเมล เปลี่ยนรหัสผ่าน หรือให้สิทธิ์ใคร

ทุกการบันทึกเรียก `/auth/v1/user` ด้วย access token และตรวจ app_metadata ปัจจุบันใหม่ ไม่อ่านรายชื่อ auth.users ทั้งตาราง ไม่ใช้ service_role key ไม่เชื่อถืออีเมล/บทบาท/หมู่บ้านที่ผู้เรียกส่งมาเอง การเปลี่ยนหรือลบ field_collector มีผลกับการบันทึกครั้งถัดไป

## เตรียม Apps Script

1. สร้างโปรเจ็กต์ Apps Script แยกสำหรับทดสอบ เพิ่ม `Code.gs`, HTML ชื่อ `Index` และ manifest จากโฟลเดอร์นี้ อย่าวางทับ Sheets bridge อย่าคัดลอก public upload/write functions จากแอปเก่าเข้ามาโดยไม่มี guard
2. ใน Project Settings → Script Properties เพิ่ม:

| ชื่อ | ค่า |
|---|---|
| SUPABASE_URL | https://uvtjjhvvtaswzhwhowlj.supabase.co |
| SUPABASE_ANON_KEY | anon/public key ของโปรเจ็กต์ เก็บใน Script Properties ไม่ใช้ service_role/secret key |
| CAPTURE_SPREADSHEET_ID | ID ชีตปลายทางที่ผู้ดูแลเลือกและมีสิทธิ์เขียน |
| CAPTURE_SHEET_NAME | ชื่อแท็บปลายทาง เช่น ผู้มีสุขภาวะพึ่งพิง |
| CAPTURE_PHOTO_FOLDER_ID | ID โฟลเดอร์ Drive สำหรับรูปภาคสนาม |

3. เตรียมหัวคอลัมน์ในแท็บปลายทาง โดยต้องมีแต่ละชื่อครั้งเดียว: `วันเวลา`, `ชื่อ-สกุล`, `ที่อยู่`, `ละติจูด`, `ลองจิจูด`, `ลิงก์รูปภาพ`, `หมู่ที่`, `ผู้บันทึก`, `รหัสรายการ` ลำดับไม่จำเป็นต้องตรงตัวอย่าง โค้ดไม่แก้หัวคอลัมน์หรือข้อมูลเก่าให้เอง รองรับไม่เกิน 10,000 แถวรวม header
4. โฟลเดอร์รูปต้องจำกัดผู้เข้าถึงตามนโยบายเทศบาล โค้ดไม่ตั้งค่า Anyone with the link และไม่เปลี่ยน sharing permissions ให้รูป หากโฟลเดอร์มีสิทธิ์สาธารณะอยู่ก่อน ต้องแก้ก่อนใช้งาน
5. Deploy Web app → Execute as Me → Who has access Anyone ได้ **สำหรับชุดโค้ดที่ตรวจสิทธิ์นี้** หน้า doGet เป็นแบบเข้าสู่ระบบเท่านั้น; doPost ไม่บันทึกข้อมูล; saveCapture ตรวจ access token/สิทธิ์ทุกครั้ง เจ้าของโปรเจ็กต์ต้องอนุญาต OAuth สำหรับ Auth HTTP requests, Sheets และ Drive
6. ทดสอบกับบัญชีและชีตทดสอบก่อน แล้วจึงอนุมัติปลายทางจริง **URL/deployment เดิมที่ยังมีฟังก์ชันบันทึกแบบไม่ตรวจสิทธิ์ต้องปิดหรืออัปเกรดทุกช่องทาง** การ deploy URL ใหม่ไม่ได้ทำให้แอปเก่าปลอดภัยขึ้น

## ข้อมูลและการตรวจสอบ

- รูป JPEG/PNG ไม่เกิน 2 MB ตรวจ MIME signature ฝั่งเซิร์ฟเวอร์ ใช้ชื่อไฟล์จากรหัสคำขอ ไม่มีชื่อผู้ป่วยในชื่อไฟล์
- รับพิกัดด้วย browser geolocation แล้วตรวจชนิด/range ตัวเลขอีกครั้ง ไม่มีการสร้างตำแหน่งแทนเมื่อรับไม่ได้ การเลือกหมู่บ้านต้องอยู่ในสิทธิ์ และข้อความที่อยู่ต้องระบุหมู่ให้ตรงกัน ยังไม่ใช่การยืนยันแนวเขต GIS ของหมู่บ้าน
- เวลาบันทึกและรหัสเจ้าหน้าที่มาจากเซิร์ฟเวอร์; ผู้เรียกไม่สามารถเลือก actor ได้ ข้อความที่อาจเป็นสูตร Sheets ถูก escape
- ใช้ Script Lock และรหัสคำขอ UUID เพื่อป้องกันส่งคำขอเดิมซ้ำ ผล duplicate หมายถึงคำขอเดิมบันทึกไปแล้ว ไม่ใช่การแก้ไขรายการเดิม ข้อมูลที่แก้ไขต้องเริ่มรายการใหม่
- ไม่มีการกำหนดรหัสผู้รับบริการหรือจับคู่ประวัติทางคลินิกอัตโนมัติ ถ้าชีตมีคอลัมน์รหัสดังกล่าว จะเว้นว่างจนกว่าผู้ดูแลตรวจสอบและกำหนดเอง
- ไม่มี endpoint สำหรับอ่านทะเบียนหรือรายชื่อเจ้าหน้าที่จากแอปนี้
- รูปและแถว Sheets ไม่ใช่ธุรกรรมเดียวกัน โค้ดตรวจผล append ก่อนลบไฟล์เมื่อผิดพลาด หากตรวจไม่ได้จะเก็บไฟล์ private ไว้ให้ผู้ดูแลกระทบยอด ไม่รับประกัน rollback แบบฐานข้อมูล
- access token อยู่ในหน่วยความจำหน้าเว็บเท่านั้น ไม่ใช้ localStorage/sessionStorage ไม่คืน refresh token เมื่อ reload/หมดอายุให้เข้าสู่ระบบใหม่ Logout ล้างข้อมูลบนเครื่องและพยายาม revoke session กับ Supabase

## การตรวจรับ

รัน `node --test tests/field-capture-app.test.mjs` จากราก repo ทดสอบโค้ด Apps Script ใน VM ด้วยข้อมูลจำลอง ครอบคลุม anonymous/expired token, สิทธิ์ที่ผู้ใช้แก้เอง, บัญชี Health Care ที่ไม่มีสิทธิ์ภาคสนาม, หมู่บ้านนอกสิทธิ์, รูปปลอม, audit actor, request ซ้ำ, สิทธิ์ถูกถอน และ append ล้มเหลว

ยังต้องทดสอบจริงใน Apps Script: ผู้มีสิทธิ์บันทึกได้ ผู้ไม่มีสิทธิ์/ถูกถอนสิทธิ์บันทึกไม่ได้ รูปและพิกัดถูกต้อง ข้อมูลเดิมไม่เปลี่ยน และ URL เก่าไม่มีทางข้าม guard ไม่มีการใช้ข้อมูลผู้ป่วยจริงหรือรหัสผ่านจริงในการทดสอบอัตโนมัติ
